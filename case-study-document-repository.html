Certa · Enterprise evidence layer · Case study

Document Repository

The problem

Documents were generated across onboarding, assessments, reviews and workflows—but users had no single place to find the right evidence, understand what it contained, trace its source or manage it over time.

Product thesis: turn fragmented documents into one persistent, searchable and traceable evidence layer.
RoleAssociate Product Manager
OwnershipEnd-to-end product ownership

01 · System context

Evidence was trapped inside individual workflows

Every stage of the third-party risk lifecycle produced files. Because those documents remained tied to the activity that generated them, retrieving evidence depended on knowing where it had entered the platform. The repository created a persistent layer across those workflows.

02 · Product definition

Define the repository around evidence jobs

I translated the fragmented-document problem into four durable jobs. These became the product model for deciding what belonged in the repository and how the experience should be structured.

01

Find

Search and filter across metadata and source.

02

Understand

Use metadata and contextual preview before opening a file.

03

Trace

Preserve source, activity and history.

04

Manage

Maintain category and expiry, then act on documents individually or in bulk.

03 · Product decisions

Make documents usable as evidence

Three decisions turned the repository from a file library into an operational evidence product.

Preserve provenance, not just the file

Source Type remained a first-class concept so users could understand where evidence entered the platform and filter by that context.

Reduce the need to open every document

The repository and preview exposed useful metadata so common questions could be answered before opening the source file.

Ship useful metadata before automating it

Manual category and expiry management created immediate value while keeping a clear path to automated classification and extraction.
